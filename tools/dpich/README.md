# dpi-ch helper

This folder contains a small project wrapper for
[`dpi-ch`](https://github.com/hyperion-cs/dpi-checkers/tree/main/ru/dpi-ch/docs),
the DPI checker from `hyperion-cs/dpi-checkers`.

The repository does not vendor the upstream binary or source tree. The wrapper
runs the official Docker image and generates a temporary `config.yaml` overlay
for project-specific targets.

## Why it is here

The June 2026 "Siberian" restriction pattern is relevant for `VLESS + REALITY`
deployments because it is described as a stateful TLS ClientHello check:

- suspicious destination subnet / ASN;
- suspicious browser-like TLS fingerprint;
- more than three near-parallel TLS attempts in roughly one minute;
- SNI participates in the short freeze context.

The current Marzban host payload generated by this repository uses
`fingerprint: chrome`, so `dpi-ch` gives us a repeatable way to test whether the
client network observes the `Siberian` symptom against Russian infrastructure,
foreign infrastructure, and project-specific IPs or domains.

## Run

Run the checker from the network you want to diagnose. A VPS run only describes
that VPS egress path; it does not prove what a mobile client sees.

Interactive TUI with default `dpi-ch` sections:

```bash
tools/dpich/run-dpich.sh
```

Add a project domain section:

```bash
tools/dpich/run-dpich.sh --target-domain example.com --name example.com
```

Check one exact VPS IP while preserving the production SNI:

```bash
tools/dpich/run-dpich.sh --target-ip 203.0.113.10 --sni example.com --name example-vps
```

Run the ALL flow and save JSON reports to `./dpich-results`:

```bash
tools/dpich/run-dpich.sh --all --target-ip 203.0.113.10 --sni example.com
```

Try a different checker fingerprint for comparison:

```bash
tools/dpich/run-dpich.sh --target-domain example.com --fingerprint firefox
```

## Interpretation notes

- `Siberian` findings are path-specific. Re-run from affected mobile/fixed
  networks before changing production profiles.
- If an IP/subnet target is tested without `--sni`, the result may miss
  SNI-bound behavior from the article. Prefer `--sni` for Reality profiles.
- Treat `fp` rotation as an A/B diagnostic, not as a blind global fix.
- If only the project IP/ASN is flagged and broad infrastructure tabs are not,
  suspect hoster/IP reputation before rewriting the whole stack.
- If `tcp 16-20` / `l4-25` is red for foreign providers while `Siberian` is not,
  the mitigation discussion should focus on path/provider/cascade rather than
  only the browser fingerprint.
